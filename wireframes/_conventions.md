# Правила вайрфреймів

> Крок 06. Спільні правила, на які спираються **усі** екрани.
> Джерела екранів і станів: [`_screens.md`](_screens.md) (замовлення) + [`../concept/sitemap.md`](../concept/sitemap.md).
> Мета вайрфрейму — довести **структуру, ієрархію і зони** екрана, а не його вигляд.
> Усе, що стосується вигляду (колір, шрифт, бренд), — пізніші кроки (tokens, design-system).

---

## 1. Деталізація — тільки структура

- Показуємо **структуру, ієрархію і зони**. Не показуємо вигляд.
- Палітра — **лише сірі** (grey-box): фон, рамки, блоки — відтінки сірого. **Жодного кольору.**
- **Ніякого** з переліченого: бренд, логотип, підібрані шрифти (тільки системний
  default), тіні, заокруглення «для краси», іконки, зображення, ілюстрації, фото.
- Зображення/аватар/графік = сірий прямокутник із текстовою міткою (напр. `[ГРАФІК: розбивка по категоріях]`).
- Кнопка виглядає як кнопка (рамка + текст), не стилізована.

## 2. Розмітка — семантичний HTML

- Тільки семантичні теги за їхнім змістом: `header`, `nav`, `main`, `section`,
  `article`, `form`, `button`, `label`, `input`, `ul/li`, `h1…h3`, `a`, `p`, `footer`.
- **Не** «суцільні `div`». `div` — лише коли жоден семантичний тег не підходить (чисте групування).
- Один `main` на сторінку; заголовки за ієрархією (`h1` → `h2` → `h3`), без перестрибувань.
- Інтерактивне — правильним тегом: дія → `button`, перехід → `a`, поле → `input`+`label`, ввід → `form`.
- Зони екрана = `section` з власним заголовком; самостійна одиниця (транзакція, банк) = `article`.

## 3. Текст — справжній, з домену

- Реальний текст з домену Бабосіка (гривні, назви банків Mono/Приват, категорії
  «Кафе», «Продукти», «Інше», місяці) — **не** `lorem ipsum` і не «заглушка».
- Тон нейтральний і робочий; фінальні формулювання UI — пізніше, тут головне зміст зони.
- Суми, дати, назви — правдоподібні (напр. `−480 ₴`, `Сільпо`, `червень 2026`).

## 4. Іменування файлів

Кожен екран = базова сторінка + окрема сторінка на кожен **нетривіальний** стан:

```
wireframes/<slug>.html            ← базова сторінка = стан УСПІХ
wireframes/<slug>-empty.html      ← порожній
wireframes/<slug>-error.html      ← помилка
wireframes/<slug>-loading.html    ← завантаження
```

- `<slug>` — короткий latin-kebab, стабільний для екрана.
- Файли станів створюємо **тільки для реальних станів** з [`_screens.md`](_screens.md)
  (де в матриці `✓`). Де `–` — файла немає.

**Slug-и екранів головного flow** (з `_screens.md`):

| Екран (sitemap.md) | slug | Файли (за реальними станами) |
|--------------------|------|------------------------------|
| Підключення банків | `bank-connect` | `bank-connect.html` (успіх), `-empty`, `-error`, `-loading` |
| Огляд за місяць | `overview` | `overview.html` (успіх), `-empty` |

## 5. Стани — окрема сторінка на кожен

- **Успіх — це базова сторінка** (`<slug>.html`), без суфікса.
- Решта станів — **окремі HTML-файли** (`-empty` / `-error` / `-loading`).
- Усі сторінки одного екрана мають **ту саму структуру і зони** — відрізняється лише **вміст**
  зон під стан:
  - **порожній** — зони на місці, замість даних заклик до дії / пояснення;
  - **помилка** — зони на місці, у зоні даних повідомлення + вихід (спробувати ще / інший шлях);
  - **завантаження** — зони на місці, у зоні даних сірі плейсхолдери «вантажиться».
- Не робимо стан модалкою чи перемикачем на одній сторінці — щоб кожен стан можна було
  відкрити прямим лінком і порівняти поруч.

## 6. Що лишаємо на потім

> Свідомо **поза** вайрфреймами — з'явиться на наступних кроках.

- Колір, палітра, тема (світла/темна) → `tokens/`
- Шрифти, типографіка, розміри → `tokens/`
- Тіні, заокруглення, відступи «під бренд», анімації
- Іконки, зображення, ілюстрації, логотип
- Готовий UI-компонент, мікрокопірайт, стани фокусу/hover
- Адаптив «під піксель» (тут — лише що складається зверху вниз / поруч)

## Чек-лист перед тим як вважати екран готовим

- [ ] Базова сторінка = стан **успіх**; на кожен `✓`-стан з `_screens.md` є окремий файл.
- [ ] Тільки сірі; ні кольору, ні бренду, ні шрифтів, ні іконок, ні картинок.
- [ ] Розмітка семантична; немає «супу з `div`»; один `main`, коректна ієрархія заголовків.
- [ ] Текст справжній з домену, не lorem.
- [ ] Структура і зони **однакові** в усіх станах одного екрана.
