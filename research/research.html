02

UX-патерни

01
Snapshot / Summary-first Вибір для MVP
Агрегат на першому плані: велика цифра, кілька карток, один-два графіки. Деталі — один клік нижче.
Де
Mint, Monobank Analytics
Підходить
Регулярний перегляд, "як справи загалом?"
Ламається
Забагато категорій → список замість дашборду
02
Chronological Feed
Транзакції від нових до старих, як соцмережа. Скрол = час. Кожен елемент — дія.
Де
Revolut, банківські виписки
Підходить
"Що я купив вчора?", пошук транзакції
Ламається
200 транзакцій нічого не скажуть про структуру витрат
03
Spatial / Visual Map Якщо 10+ категорій
Гроші як простір. Treemap або bubble chart — розмір фігури = сума. Категорії видно за секунду через площу.
Де
Spendee (bubble), BI-інструменти
Підходить
Побачити пропорції миттєво без читання цифр
Ламається
Мобільний, порівняння місяців, відсутність даних
04
Goal / Budget Contrast Не для MVP
Кожна категорія в контексті бюджету: "витратив 3200 з 4000". Прогрес-бари, червоне/зелене.
Де
YNAB, Every Dollar
Підходить
Сформована фінансова дисципліна, є бюджети
Ламається
Без бюджетів — порожні бари. Бюджети відкладені на post-MVP.
05
Query / Intent-first
Користувач формулює питання через фільтри або природну мову. Немає фіксованого "головного екрану".
Де
Google Finance, AI-асистенти, Notion
Підходить
Досвідчений користувач, нестандартні питання
Ламається
Без звички — blank state, розгубленість. Дорогий у розробці.
Вибір для Бабосіка
Snapshot / Summary-first
  • MVP вже визначив: аналітика по категоріях, порівняння місяць-до-місяця, топ витрат — це і є дашборд.
  • Швидкість без спінерів (принцип CLAUDE.md) — агрегати кешуються, сторінка відкривається миттєво.
  • Десктоп як основний — дашборд масштабується природно: сітка карток, графік збоку.
Другий — за умови 10+ категорій
Spatial / Visual Map (Treemap)
  • Додається як альтернативний вигляд аналітики — перемикач List / Map.
  • Дає миттєве розуміння пропорцій там, де дашборд перетворюється на довгий список.
Не підходить
Goal / Budget Contrast
  • Бюджети та цілі явно відкладені на наступні ітерації (CLAUDE.md).
  • Без бюджетів інтерфейс виглядає зламаним: порожні прогрес-бари, заклики без контексту.

05

Висновки

  • Користувачі хочуть автоматизацію (не вводити вручну), але контроль (виправити, перекатегоризувати).
  • Категорії — ключова фіча: стандартні не підходять всім.
  • Аналітика має бути зрозумілою з першого погляду, не вимагати фінансових знань.
  • Дизайн: дружній і живий, не банківський.
