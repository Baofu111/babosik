UX-патерни

01
Snapshot / Summary-first Вибір для MVP
Агрегат на першому плані: велика цифра, кілька карток, один-два графіки. Деталі — один клік нижче.
Де
Mint, Monobank Analytics, більшість фінтех-застосунків
Підходить
Регулярний перегляд (щотижня/щомісяця). "Як справи загалом?"
Ламається
Забагато категорій → список замість дашборду. Погано для першого знайомства з даними.
02
Chronological Feed
Транзакції від нових до старих, як соцмережа. Скрол = час. Кожен елемент — дія.
Де
Revolut (основний екран), банківські виписки
Підходить
"Що я купив вчора?" — пошук конкретної транзакції, перевірка списань
Ламається
Непридатний для розуміння патернів. 200 транзакцій за місяць нічого не скажуть про структуру витрат.
03
Spatial / Visual Map Якщо 10+ категорій
Гроші як простір. Treemap або bubble chart — розмір фігури = сума. Категорії видно за секунду через площу.
Де
Spendee (bubble), фінансові BI-інструменти
Підходить
Багато категорій, потрібно побачити пропорції миттєво без читання цифр
Ламається
Мобільний — bubble charts нечитабельні. Порівняння двох місяців складне. Нові користувачі без даних — пустий екран.
04
Goal / Budget Contrast Не для MVP
Кожна категорія завжди в контексті бюджету: "витратив 3200 з 4000". Прогрес-бари, червоне/зелене.
Де
YNAB, Every Dollar
Підходить
Користувач вже сформував фінансову дисципліну, знає свій бюджет, хоче контролювати відхилення
Ламається
Без заданих бюджетів — порожні бари. Додає когнітивне навантаження ("а скільки взагалі планувати?")
05
Query / Intent-first
Користувач формулює питання через фільтри або природну мову. Немає фіксованого "головного екрану".
Де
Google Finance, AI-фінансові асистенти, Notion
Підходить
Досвідчений користувач, нестандартні питання ("скільки на таксі у вихідні")
Ламається
Вимагає знати, що запитати. Без звички — blank state, розгубленість. Висока вартість розробки AI-варіанту.
Вибір для Бабосіка
Snapshot / Summary-first
  • MVP вже це визначив — "аналітика по категоріях за місяць", "порівняння місяць-до-місяця", "топ витрат" — це і є дашборд.
  • Швидкість без спінерів (принцип з CLAUDE.md) — агрегати кешуються, сторінка відкривається миттєво.
  • Десктоп як основний — дашборд масштабується на широкий екран природно: сітка карток, графік збоку.
Другий — за умови 10+ категорій
Spatial / Visual Map
  • Якщо користувач має розгалужену структуру (їжа → кафе/магазин/доставка), treemap дає миттєве розуміння пропорцій.
  • Додається як альтернативний вигляд аналітики — перемикач List / Map.
Не підходить
Goal / Budget Contrast
  • Бюджети та цілі — явно відкладено на наступні ітерації.
  • Без бюджетів інтерфейс виглядає зламаним: порожні прогрес-бари, заклики "встановити ліміт" без контексту.

Висновки

  • Користувачі хочуть автоматизацію (не вводити вручну), але контроль (виправити, перекатегоризувати)
  • Категорії — ключова фіча: стандартні не підходять всім
  • Аналітика має бути зрозумілою з першого погляду, не вимагати фінансових знань
  • Дизайн: дружній і живий, не банківський
