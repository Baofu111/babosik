архітектура

Від jobs до екранів: сутності → sitemap → навігація → потоки → трасування. Усе виведено з того, що людина намагається зробити, а не зі структури конкурентів. Потоки оновлені після власного розбору дефектів (стани, виходи з тупиків, глибина RJ-2).

01

Sitemap — дерево екранів

Групування за об'єктами і логікою людини. Біля кожного екрана — job, який він обслуговує. Глибина мінімальна свідомо.

JOB який job закриває P критично для primary (Олена) S критично для secondary SIROTA екран без job
Бабосік
Вхід / Реєстрація SIROTA Жоден job не прагне реєстрації — у jobs вона тертя (RJ-5, EJ-2). Рішення: прив'язано до onboarding (Flow A) як мінімальний крок, не самостійне призначення.
① Моя картина витрат об'єкт: Місячна картина
Огляд за місяць MJ · RJ-3 P Домашній екран. Загальна сума, розбивка по категоріях, топ позицій, підсвітка перевищень.
Порівняння місяців RJ-4 S Цей місяць проти попереднього.
② Транзакції об'єкт: Транзакція
Список транзакцій RJ-2 P Знайти те, що «потрапило не туди» / без назви.
Транзакція: правка RJ-2 P Перенести в категорію, дати назву. Створення категорії — інлайн у пікері.
③ Мої категорії об'єкти: Категорія, Підкатегорія
Категорії та підкатегорії: керування RJ-2 P CRUD власних категорій/підкатегорій. Ядро MVP, пріоритет №1 (диференціатор).
④ Джерела даних об'єкт: Підключення банку
Підключення банків RJ-1 P Додати банк, бачити статус. Перший раз — також RJ-5 (перший екран з даними).
Backlog — поза MVP-скоупом
Додати транзакцію вручну SIROTA → backlog Сутність «ручна транзакція» під питанням, суперечить духу RJ-1. Повернути, коли підтвердиться готівковий сценарій (доресерч: ~34,6% суми — готівка).
Експорт даних Г-4 → backlog Гіпотеза vendor lock-in (Максим). Додати в Акаунт наступною ітерацією.
Наскрізне (не екрани): перший прохід (onboarding) — послідовність ④ → ① без проміжного «налаштуй спочатку». Тон «контроль, не провина» (EJ-1) — наскрізна non-functional якість усіх екранів, не екран і не клітинка матриці.
02

Потоки

Три ключові related jobs. Кожен має happy-path, стани (empty/error/loading) і обидва кінці — успіх і тупик. Версія після ревізії: додано виходи з тупиків і відсутні стани.

Flow A — Зібрати картину без рутини

RJ-1 (+ RJ-5, EJ-2)

Реєстрація → підключив банк → одразу бачу картину. Порожній Огляд тепер пропонує дію; помилка доступу має escape.

flowchart TD
  Start(("Старт: перший вхід")) --> Reg["Вхід / Реєстрація"]
  Reg --> RegLoad(["loading: авторизація"])
  RegLoad --> RegOk{"Вхід успішний?"}
  RegOk -->|ні| RegErr(["error: вхід не вдався"])
  RegErr --> Reg
  RegOk -->|так| Conn["Підключення банків"]
  Conn --> ConnEmpty(["empty: ще немає підключень"])
  ConnEmpty --> Auth{"Доступ до банку надано?"}
  Auth -->|ні| AuthErr(["error: доступ відхилено / токен невірний"])
  AuthErr --> AuthRetry{"Спробувати ще раз?"}
  AuthRetry -->|так| Conn
  AuthRetry -->|ні| Help(("ВИХІД: допомога / інший банк / пізніше"))
  Auth -->|так| Load(["loading: тягнемо транзакції"])
  Load --> Sync{"Синхронізація успішна?"}
  Sync -->|ні| SyncErr(["error: збій синхронізації"])
  SyncErr --> Conn
  Sync -->|так| HasTx{"Є транзакції за період?"}
  HasTx -->|ні| OvEmpty(["empty: Огляд ще порожній — дані тягнуться"])
  OvEmpty --> OvAction{"Дія з порожнього стану?"}
  OvAction -->|"оновити / зачекати"| Load
  OvAction -->|"підключити ще банк"| Conn
  OvAction -->|"проігнорував"| Drop(("ТУПИК: закрив, не повернувся"))
  HasTx -->|так| Overview["Огляд за місяць"]
  Overview --> Done(("УСПІХ: бачить свою картину"))
  classDef happy fill:#0e1e18,stroke:#34d399,color:#e8e8ed;
  classDef dead fill:#1d1010,stroke:#f87171,color:#e8e8ed;
  classDef exit fill:#111220,stroke:#818cf8,color:#e8e8ed;
  class Overview,Done happy;
  class Drop dead;
  class Help exit;

Flow B — Привести картину до свого життя

RJ-2

Контекстний тап по «Інше» = 2 тапи. Категорію створює інлайн у пікері, без переходу на екран керування → happy-path ≤ 3 тапів.

flowchart TD
  Start(("Старт")) --> Overview["Огляд за місяць"]
  Overview -->|"тап по «Інше» (контекст, 2 тапи)"| TxLoad(["loading: вантажимо транзакції"])
  Overview -->|"вкладка Транзакції"| TxLoad
  TxLoad --> TxLoadOk{"Список завантажився?"}
  TxLoadOk -->|ні| TxErr(["error: не вдалось завантажити"])
  TxErr --> TxLoad
  TxLoadOk -->|так| TxList["Список транзакцій"]
  TxList --> Found{"Знайшла потрібну транзакцію?"}
  Found -->|ні| ListEmpty(["empty: за фільтром нічого"])
  ListEmpty --> Alt{"Що далі?"}
  Alt -->|"уточнити пошук"| TxList
  Alt -->|"готівка - додати"| ManualBL(("ВИХІД: ручне додавання (backlog)"))
  Alt -->|"здалась"| GiveUp(("ТУПИК: не знайшла, покинула"))
  Found -->|так| TxEdit["Транзакція: правка"]
  TxEdit --> CatExists{"Категорія вже існує?"}
  CatExists -->|ні| NewCat(["контекст: + Нова категорія інлайн"])
  NewCat --> NewCatOk{"Створилась?"}
  NewCatOk -->|ні| CatErr(["error: не вдалось створити"])
  CatErr --> TxEdit
  NewCatOk -->|так| Save(["loading: зберігаємо"])
  CatExists -->|так| Save
  Save --> Saved{"Збереглось?"}
  Saved -->|ні| SaveErr(["error: не вдалось зберегти"])
  SaveErr --> TxEdit
  Saved -->|так| Overview2["Огляд за місяць"]
  Overview2 --> Done(("УСПІХ: картина = реальне життя"))
  classDef happy fill:#0e1e18,stroke:#34d399,color:#e8e8ed;
  classDef dead fill:#1d1010,stroke:#f87171,color:#e8e8ed;
  classDef exit fill:#111220,stroke:#818cf8,color:#e8e8ed;
  class Overview2,Done happy;
  class GiveUp dead;
  class ManualBL exit;

Flow C — Зрозуміти чи я змінююсь

RJ-4

Порожній стан (один місяць даних) повертає в Огляд, а не лишає в тупику.

flowchart TD
  Start(("Старт")) --> Overview["Огляд за місяць"]
  Overview -->|"перемикач «Порівняння»"| HasPrev{"Є попередній місяць даних?"}
  HasPrev -->|ні| CompEmpty(["empty: лише один місяць"])
  CompEmpty --> Wait(("М'який вихід: прийти за місяць"))
  Wait --> Overview
  HasPrev -->|так| Load(["loading: рахуємо порівняння"])
  Load --> Calc{"Дані дорахувались?"}
  Calc -->|ні| CalcErr(["error: не вдалось порахувати"])
  CalcErr --> Overview
  Calc -->|так| Compare["Порівняння місяців"]
  Compare --> Done(("УСПІХ: бачить динаміку"))
  classDef happy fill:#0e1e18,stroke:#34d399,color:#e8e8ed;
  classDef exit fill:#111220,stroke:#818cf8,color:#e8e8ed;
  class Compare,Done happy;
  class Wait exit;

Екрани: S1 Вхід/Реєстрація · S2 Огляд за місяць · S3 Порівняння місяців · S4 Список транзакцій · S5 Транзакція: правка · S6 Категорії та підкатегорії · S7 Підключення банків · S8 Додати вручну

Сироти → рішення. S1 Вхід/Реєстрація — прив'язано до onboarding (технічний шлюз). S8 Додати вручну — backlog. Г-1 (соціальний) — backlog. Г-4 (експорт) — backlog → Акаунт пізніше. Після рішень у живому MVP-скоупі (S2–S7 × MJ–EJ-2, Г-2) порожніх рядків і стовпців немає.
EJ-1 «контроль, не провина» прибрано з матриці: це наскрізна non-functional якість (тон), яку жоден екран не закриває дією. Винесено в наскрізні критерії, щоб не створювати хибне відчуття покриття.
Найгустіша колонка — S2 Огляд за місяць (6 jobs). Несуча конструкція продукту й домашній екран. Ризик перевантаження — стежити на вайрфреймах.
